# Как предложить модуль

Это источник модулей от автора Aster Mail и место для предложений сообщества.
Откройте issue с описанием сценария или pull request с модулем в отдельной папке.
Публикация здесь не означает автоматическую проверку безопасности или включение
модуля в Aster Mail.

Прочитайте [SDK](docs/sdk/README.md), [руководство](docs/sdk/development.md) и
[AGENTS.md](AGENTS.md). Новые возможности host оформляйте отдельным изменением
контракта. В pull request включите:

- `module.json`, готовые браузерные JS/HTML/CSS и явный список `files`.
- README: назначение, совместимость, установка, настройка, права сервиса и ограничения.
- LICENSE/NOTICE для кода и ресурсов с сохранением атрибуции. Не включайте секреты
  и проприетарные SDK без права распространения.
- Проверки успеха, отказов, неопределённых записей, смены аккаунта и отказа в правах.
- Для UI — снимки, клавиатуру, светлую/тёмную тему, масштабы 100/150/200%.

Используйте минимальные права и точные HTTPS origins. Панели должны быть адаптивными,
с подписями полей, загрузкой и явными ошибками. Не меняйте DOM основного приложения,
не отправляйте письма/приглашения: предлагайте изменения в черновик для проверки
пользователем. Не используйте реальные почтовые ящики для тестов отправки.

Повышайте версию пакета при изменении файлов. Проверяйте его авторитетным
`scripts/check-module.cjs` совместимой ветки Aster Mail.
