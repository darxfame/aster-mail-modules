# Правила каталога модулей

Источник каталога — файл `catalog.json` в корне
[darxfame/aster-mail-modules](https://github.com/darxfame/aster-mail-modules).
Это каталог модулей от автора [Aster Mail](https://github.com/darxfame/aster-mail)
и место, где сообщество может предложить свои модули через pull request.

## Неизменяемая запись выпуска

Схема — [catalog.schema.json](../catalog.schema.json), `schemaVersion: 1`.
Корневое поле `modules` содержит не более 200 записей, одну актуальную на каждый `id`.
Прошлые версии доступны в Git-истории. Неизвестные поля/разрешения и дубликаты ID
отклоняются. Публичные поля записи:

```json
{
  "id": "company.meetings",
  "name": "Company meetings",
  "version": "1.0.0",
  "source": {
    "repository": "https://github.com/example/modules",
    "commit": "0123456789abcdef0123456789abcdef01234567",
    "directory": "meetings"
  },
  "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "permissions": ["ui"],
  "networkOrigins": [],
  "networkHeaders": [],
  "host": { "apiVersion": 1, "features": [] }
}
```

Это вымышленный пример, не запись для установки. Для пакетов с расширениями
добавляются точные декларации `meetingLinks` и `authentication`. Поле `host.features`
задаёт требуемые возможности клиента: `meeting.launch`, `auth.session`,
`rpc.error-details`, `network.origin-grants`. Клиент должен отказать при отсутствии или неизвестном значении
требования; API version `1` сам по себе не подтверждает наличие расширений.

`npm run check:catalog` проверяет запись по локально доступному pinned Git commit;
с `ASTER_MAIL_HOST=/path/to/compatible-host` дополнительно использует авторитетный
валидатор host. Для внешнего репозитория клиент должен загрузить snapshot из
указанного источника, а не искать похожую папку локально.

Каждая запись фиксирует:

- Идентификатор и версию пакета, совпадающие с его `module.json`.
- Публичный GitHub-репозиторий и относительную папку пакета.
- Полный 40-символьный commit SHA с исходниками; ветки и теги не заменяют pin.
- SHA-256 пакета, рассчитанный авторитетным валидатором Aster Mail.
- Точный набор разрешений манифеста. Origins сети, запуска и аутентификации также
  должны совпасть с проверяемым манифестом и показываться пользователю.
- Требования к host и ограничения совместимости.

SHA-256 — не хеш архива GitHub, не хеш одного module.json и не подпись издателя.
Это fingerprint `readPackage/fromFiles` Aster Mail: отсортированные пути `module.json`
и объявленных `files`, для каждого UTF-8 путь, нулевой байт, затем бинарный SHA-256
содержимого. Итоговый SHA-256 потока записывается в lowercase hex.

Сначала опубликуйте commit с готовым пакетом, затем отдельным commit добавьте
запись каталога, ссылающуюся на него. Не пытайтесь включить SHA текущего коммита
в этот же commit. Обновление пакета требует новой версии, нового commit, fingerprint
и повторной проверки разрешений. Нельзя переиспользовать версию с иным содержимым,
двигать существующий release tag или скрытно расширять права.

## Повторная проверка перед установкой

Клиент не доверяет записи каталога как достаточному подтверждению:

1. Проверяет структуру записи, ID/версию, полный commit SHA, SHA-256 и разрешения.
2. Загружает manifest и только явно объявленные ресурсы по immutable URLs этого SHA.
   Не использует текущий HEAD, mutable ref, Git credentials, hooks, npm или submodules.
3. Повторно запускает авторитетные проверки API/version, origins/headers, путей,
   списка файлов и лимитов host. Не исполняет код пакета на этом этапе.
4. Пересчитывает fingerprint и сравнивает его, ID/версию и точный набор разрешений
   с записью каталога. Проверяет заявленные ограничения host и origins.
5. При любом несовпадении, недоступности, неподдерживаемом контракте или ошибке проверки
   **отказывает в установке**. Нельзя выбирать другой commit или отключать проверку.
6. Показывает источник, commit, SHA-256, разрешения, origins и совместимость; получает
   пользовательское подтверждение. Устанавливает пакет выключенным. Включение и выдача
   прав — отдельное действие текущего аккаунта.

Установленная копия повторно проверяется перед исполнением по правилам host.
Каталог не разрешает автоматическое обновление/включение, отправку писем и приглашений,
доступ к чужому аккаунту или обход изоляции. Смена аккаунта отменяет загрузку.
Никаких секретов, реальных данных аккаунта и private repos в публичном каталоге.

## Предложения сообщества

Для нового модуля приложите пакет, README, лицензию, проверки и будущую запись
каталога с immutable pin. Публикация записи не доказывает репутацию автора и не
заменяет независимую проверку новых возможностей host. См. [CONTRIBUTING.md](../CONTRIBUTING.md).

Поле `optionalOrigins` закрепляется рядом с остальными возможностями и должно
в точности совпадать с manifest. Оно разрешает только запросить у пользователя
доступ к точному HTTPS origin; не выдаёт доступ всему семейству автоматически.
Тип `authentication.type` для нового пакета — `browser-token` с явными capture
и authorization из manifest; провайдерный адаптер в host не требуется.
