# Совместимость ktalk 0.1.1 с общим SDK

Изменены декларация входа и выбор сервера. Список прав, внешние записи и API
создания комнаты не расширены. Поля session JSON и схема Session находятся
в manifest пакета; host не содержит провайдерного адаптера.

Доступ к новому поддомену ktalk.ru выдаётся только после нативного подтверждения
точного HTTPS origin. Без разрешения данные не сохраняются и запросы не уходят.
Проверены отказ и согласие, неизменность предыдущего ключа при отказе,
привязка токена к origin и изоляция аккаунта. IdP остаются явно объявленными.

Node: 11 проверок проходят. Авторитетный SDK принимает пакет. В реальном Electron
с вымышленными данными проверены grant, изолированный вход, шифрованная передача
токена, отсутствие токена в каталоге, HTTP 404 через contextBridge, единичное
создание, запрет повтора, сохранность черновика, 100/150/200%, выход и retirement.
Ни реальный OWA, ни живой сервер Толка не использовались. Windows и реальный SSO
корпоративного пространства остаются отдельной приёмкой провайдера.

До публикации каталог должен закрепить полный commit этого пакета и digest,
проверенные `check:catalog` с авторитетным host. Пакет сначала фиксируется
отдельным коммитом; запись каталога — следующим. Пользователь получает готовый
совместимый клиент, а не инструкции по применению SDK patch.
