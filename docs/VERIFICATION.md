# Проверка выпуска v0.1.11

12 ноября 2026 года, macOS Apple Silicon, SDK Aster Mail 0.2.12.

- На исходной версии воспроизведена ложная блокировка для sipSettings={} и
  roomStream={isEnabled:false,isActive:false,viewersCount:0}: protected=true.
- Повторно прочитаны актуальные схемы RoomSipSettings и TalkRoomStream
  [официального API](https://developer.kontur.ru/doc/talk.public.api).
  sipNumber/sipUri/phoneNumbers помечены readOnly; roomStream имеет отдельные
  isEnabled/isActive/viewersCount. Сам объект не является признаком включения.
- Пустые объекты и SIP-реквизиты больше не блокируют новый случайный адрес.
  Защита PIN, названия/описания, участников/модераторов, залов и включённой/активной
  трансляции сохранена. Неверные типы используемых полей блокируют запись.
- 26 Node-тестов: пустые и заполненные read-only SIP-реквизиты, выключенная
  трансляция, HTTPS-ссылка в location/body, один PUT, отсутствие SIP/streamKey
  в журнале и черновике, прежние отказы и неопределённые записи.
- Нативный fixture использует GET с SIP-реквизитами и выключенной трансляцией;
  проверяет создание, повторное использование в календаре, HTTPS location/body,
  обновление, сохранность настроек, sandbox, SSO и интерфейс на 100/150/200%.
- Поля журнала разделены; старые записи с protected показывают прежний сохранённый
  результат до следующей попытки, не переинтерпретируются. Схема настроек остаётся 1.
  Новых прав, origins, зависимостей и изменений SDK нет. Только флаги, без SIP-адресов,
  телефонов, streamKey, токенов и сырых ответов. UI использует textContent/value.

Точный корпоративный ответ не считывался; вывод пользователя выявил агрегированный
флаг, ошибка проверки воспроизведена на вымышленных данных. Корпоративная запись
и Windows остаются непроверенными. API по-прежнему upsert, не атомарный create-only;
используется новый случайный UUID и нет повторов неопределённых записей.

# Проверка выпуска v0.1.10

12 ноября 2026 года, macOS Apple Silicon, совместимый SDK Aster Mail 0.2.12.

## Установленный контракт Толка

- Прочитаны GET/PUT Rooms, схемы TalkRoom/TalkRoomParams и разделы авторизации,
  областей действия и ролей [официального API](https://developer.kontur.ru/doc/talk.public.api).
  GET описан как получение настроек, а не атомарная проверка существования.
- Анонимный GET случайного UUID-адреса на публичном `demo.ktalk.ru` вернул HTTP 200,
  совпавший roomName, пустые moderators/anonymousModerators/onlineUsers/sessionHalls,
  без title. Выполнялось только чтение: без PUT, входа, приглашений и подключения.
  Сырые ответы, серверные идентификаторы и cookies в репозиторий не включены.
- Изучен публичный [Outlook add-in](https://app.ktalk.ru/add-in/outlook/index.html):
  ресурс `main.66af877fc0a3629e4b65.js`, SHA-256
  `037f776caf71d20a697a056e3cd1905a1dde814b56b52076492f1e68e31db4dc`.
  Для нового адреса он генерирует UUID; GET читает параметры выбранной существующей
  комнаты. Дальнейшее сохранение выполняет PUT. Код не копировался.
- Дополнительно просмотрен публичный web-клиент `master-079e4451`, ресурс
  `main.def5bd9f5f5d9f82.js`, SHA-256
  `31905f3c07339c5cf88f00076bfdb89963a51a43bbff06856a8318ea9bd92b90`:
  GET используется как getRoomInfo, PUT как updateRoomInfo.

## Проверки изменения

- 25 Node-тестов: GET 200 с вымышленными настройками наблюдаемой формы, GET 404,
  настроенная/активная комната, неверный roomName/формат, отказы HTTP, потеря ответа,
  отсутствие повторов и сохранность намерения при сбоях хранилища.
- Реальный Electron: тот же GET 200 через sandbox/RPC, один PUT, сохранённые результаты,
  миграция/обновление, отсутствие токенов в выводе, прежние SSO/logout и смена аккаунта.
  UI проверен на 100/150/200%, адрес доступен для копирования, результаты читаемы
  при свёрнутых настройках подключения. Снимки обновлены.
- Новых разрешений, сетевых origins, SDK-возможностей и зависимостей нет.
  Одна запись lastAttempt хранится в прежнем зашифрованном профиле settingsVersion 1;
  её отсутствие у прежних установок допустимо. Миграция не удаляет старый pending.
  Проверены вызовы create, календарная команда, check, settings, reset и панель.
- Успешный GET не разрешает произвольную запись: используется только новый случайный
  адрес модуля, явные признаки настроенной/активной комнаты и неверный ответ блокируют PUT.
  Это эвристика, а не доказательство отсутствия ранее сохранённой пустой комнаты;
  атомарного create-only контракта API не предоставляет. 128-битный UUID ограничивает
  риск коллизии, а PUT после неопределённого ответа никогда не повторяется.
- Журнал проверки содержит локально сгенерированный адрес/время, фиксированные виды
  результата, статус ошибки и флаги/счётчики. Сырые ответы, service IDs, названия,
  имена участников, токены и заголовки не копируются. UI использует textContent/value.

Реальные запись в корпоративный Толк, корпоративные права и Windows не проверены.
Причина ложной коллизии подтверждена реальным публичным GET; запись проверена только
на вымышленных ответах в настоящем Electron, не выдаётся за корпоративную приёмку.

# Проверка выпуска v0.1.9

Выполнено 12 ноября 2026 года на macOS Apple Silicon с Aster Mail 0.2.12.

- На исходной версии воспроизведён GET 403 при сохранённой SSO-сессии: общий текст
  «Не удалось подтвердить создание комнаты», без PUT и без записи pending.
- `npm run check`, `npm test`: 21 успешная проверка, включая RU/EN, GET 401/403/429/500,
  потерю ответа, коллизию, отклонённую и неопределённую запись, отсутствие повторов.
- Нативный Electron fixture проверил HTTP-статусы через настоящий sandbox/contextBridge,
  сохранённую сессию при отказе доступа, отсутствие PUT после неуспешного GET,
  прежние создание, обновление с миграцией настроек, logout и смену аккаунта.
- Светлая/тёмная панели, 100/150/200%, отсутствие переполнения и доступность нижних
  элементов проверены в WebContentsView; обновлены снимки интерфейса.
- Права, сетевые origins, способ авторизации, схема настроек и правила записи не менялись.
  Сообщения строятся из фиксированного словаря и числового HTTP-статуса, без ответа сервиса,
  адресов и секретов. Входные/выходные границы sandbox остаются прежними.

Реальные корпоративные API/SSO и Windows не проверялись. Фактическая причина
сообщённого пользователем отказа пока не установлена: прежняя версия скрывала
статус предварительного запроса. Выпуск исправляет сообщения, а не заявляет
исправление неизвестной ошибки сервера. Реальных комнат и приглашений не создавалось.

# Проверка выпуска v0.1.1

Выполнено 4 ноября 2026 года на macOS Apple Silicon.

- `npm run check`: синтаксис JS, JSON, наличие ресурсов; пакет принят авторитетным
  `readPackage` совместимого host.
- `npm test`: 9 успешных проверок модуля, упаковки другого сервера и каталога.
- Aster Mail с расширением SDK: `npm run check`; Node — 331 успешно, 1 пропущен,
  ошибок нет. Дополнительные проверки auth/native routing входят в этот запуск.
- `npm run test:modules`: существующая песочница, запрет Node/file/direct network,
  границы аккаунта и встроенная панель в настоящем Electron.
- `npm run test:connection`: обычный form login, gzip и первое чтение на вымышленном
  loopback-сервере в настоящем Electron.
- `scripts/test-native.cjs`: реальный sandbox runtime Толка, отдельное окно
  корпоративного входа с перехваченным сайтом, захват вымышленной сессии, настоящий
  `LocalStore` + Electron `safeStorage`, отсутствие открытого токена в файле,
  восстановление зашифрованной сессии, отсутствие токена в ответах SDK/каталоге,
  GET 404 через contextBridge и ровно один PUT, сохранение описания черновика,
  удаление сессии и остановка входа при смене аккаунта.
- Панель проверена в настоящем WebContentsView на 100/150/200%, в светлой/тёмной
  теме, без горизонтального переполнения, с прокруткой и фокусом нижнего поля.
  Снимки — [screenshots](screenshots/README.md).
- ОС определяет обработчик `ktalk://` как `Толк.app` (установлен Толк 3.7.0).
- Патч host проходит `git apply --check` на чистом `baseCommit` из `host/provenance.json`.

Не проверены: Windows, настоящий корпоративный SSO/IdP, реальные токены и права API,
серверное создание комнаты, запуск и подключение к реальной конференции. Тестовые
ответы сервиса вымышленные; реальных писем, приглашений и комнат не создавалось.
Независимый review границ нового SDK и платформенная приёмка нужны до production.

Анонимная проверка опубликованного каталога доступна после push:

```sh
ASTER_MAIL_HOST=/path/to/compatible-host /path/to/compatible-host/node_modules/.bin/electron scripts/check-remote.cjs
```

Она повторно загружает `catalog.json` с GitHub, скачивает пакет по pinned commit,
проверяет fingerprint, разрешения, origins и совместимость. Код пакета не исполняется.
