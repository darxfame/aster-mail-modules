# Каталог одобренных модулей

Aster Mail читает список из `catalog.json` основной ветки этого репозитория.
Только запись в каталоге означает одобрение конкретной версии автором. Наличие
папки, открытого Pull Request или Issue само по себе не добавляет модуль в список.

Пока проверенные пакеты не опубликованы, `modules` остаётся пустым. Не добавляйте
черновые пакеты или вымышленные версии ради заполнения списка.

## Публикация пакета

1. Подготовить самостоятельный пакет по API Aster Mail и правилам разработки.
2. Пройти review кода, разрешений, внешних сервисов и лицензий. Проверить отказ
   в правах, смену аккаунта, обрыв сети и отсутствие повторов внешних записей.
3. Опубликовать готовый пакет отдельным коммитом в этом репозитории.
4. Выполнить в рабочей копии Aster Mail `node scripts/check-module.cjs <folder>`
   и сохранить точный SHA-256 `digest`.
5. Следующим коммитом добавить запись в `catalog.json`:

```json
{
  "catalogVersion": 1,
  "modules": [
    {
      "manifest": {},
      "description": "Описание назначения и сценария модуля",
      "commit": "полный SHA опубликованного коммита с пакетом",
      "directory": "путь/к/пакету",
      "digest": "SHA-256 из check-module.cjs"
    }
  ]
}
```

Пример выше — структура, не готовая запись: `manifest` заменяется полным
`module.json` пакета, SHA — реальными значениями. `directory` может быть пустой
строкой, если пакет находится в корне. Все пакеты каталога находятся в этом
репозитории. Допускается до 20 уникальных модулей и 512 КиБ метаданных.

Кнопка «Подключить» в карточке одновременно устанавливает и разрешает
перечисленные возможности текущему аккаунту. Поэтому клиент перед кликом
показывает разрешения и сетевые адреса, а перед установкой заново проверяет
каталог, commit, manifest и digest. Дополнительные разрешения нельзя вводить
незаметно обновлением файлов. Автоматические обновления не выполняются.

## Предложения и отзыв

Готовый модуль предложите через Pull Request; идею — через Issue. До слияния и
явного добавления записи модуль не считается одобренным. Чтобы отозвать новую
установку версии, удалите её из `modules`: новые подключения будут отклонены.
Уже установленный пакет не удаляется автоматически и отключается пользователем.

Код сервиса, авторизация, ресурсы и тесты пакета принадлежат этому репозиторию.
В репозиторий Aster Mail входят только общие контракты и механизм каталога/SDK.
