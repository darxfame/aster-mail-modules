# Обновление и миграции настроек


В каталоге новая версия установленного ID показывает «Обновить с сохранением
настроек». Пакет заново загружается по immutable commit и проверяется. Удаление
перед обновлением не требуется. Сохраняются `data`, включённость, совместимая
сервисная сессия и точные origin grants; данные разных аккаунтов не смешиваются.
Расширение возможностей или смена источника требуют отдельного подтверждения.
Несовместимая схема сессии не переносит токен в новый способ авторизации.

Версия данных задаётся независимо от версии пакета: `settingsVersion` (по умолчанию
1). Если схема не меняется, настройки сохраняются целиком, включая API-ключи и
неопределённые результаты внешних записей. Например:

```json
{
  "settingsVersion": 2,
  "settingsMigrations": [{
    "from": 1,
    "to": 2,
    "operations": [
      {"op":"rename","from":["apiKey"],"path":["credentials","token"]},
      {"op":"setDefault","path":["appearance","theme"],"value":"light"}
    ]
  }]
}
```

Первый контракт поддерживает последовательные шаги `n → n+1`, переименование
JSON-полей без перезаписи существующего назначения и установку отсутствующих
значений. Удалений и произвольного исполнения кода в main нет. Пути работают с
объектами, не индексами массивов; целые массивы можно переносить как значения.
Для сложного преобразования, не покрытого контрактом, сначала расширяется SDK
с тестами. Нельзя молча очистить настройки или заменить отсутствующую миграцию
инициализацией. Новый пакет при первой установке инициализирует пустые настройки
своим обычным кодом; миграции применяются к ранее сохранённым данным.

Миграция выполняется на копии данных, в порядке схем, без сети и до переключения
версии. Нет шага, конфликт ключей, неизвестная операция, превышение 16 КБ или
ошибка шифрованного сохранения — старая запись остаётся. Финальные версия пакета,
схема и настройки записываются вместе через атомарный LocalStore. Во время
операции нельзя запускать/удалять/переключать модуль; активные команды и окно входа
нужно сначала завершить. После обновления runtime запускается заново; SDK не
повторяет создание комнат и не отправляет приглашения.

Автоматических обновлений нет. Старые package snapshots пока сохраняются на диске;
они не исполняются без текущей записи аккаунта. История settings-backup и ручной
rollback с понижением схемы — следующие отдельные возможности, не автоматический
откат после произвольного server write. При проблеме уже активированной версии
публикуется исправление с новой версией пакета и проверенным преобразованием схемы.
