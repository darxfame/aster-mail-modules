# Контур.Толк для Aster Mail

Пакет `ru.ktalk.meetings`, версия `0.1.9`.

Создаёт комнаты, поддерживает корпоративный вход и API-ключ, предлагает ссылки
в черновик новой встречи и запускает установленный десктопный Толк после нажатия
«Подключиться» в карточке встречи или виджете. Открытие карточки само по себе
не подключает к конференции и не меняет ответ на приглашение.

## Установка и настройка

Установите модуль «Контур.Толк» из каталога в релизной версии Aster Mail
с поддержкой модулей. Проверьте запрашиваемые разрешения, подтвердите установку.
Настройки доступны сразу после установки, без входа в Exchange.
Для описанного ниже интерфейса календаря обновите Aster Mail до 0.2.8 или новее.

Для корпоративного SSO укажите адрес пространства компании, например
`https://company.ktalk.ru`. Поле сервера изначально пустое; общий вход в аккаунт
Контура через `app.ktalk.ru` этой кнопкой не запускается.
Укажите сервер с `https://` или без него, сохраните настройки. При смене сервера
прежний ключ не переносится. Незавершённый результат создания нужно сначала проверить
и завершить. Готовая ссылка `https://app.ktalk.ru/test_room` поддерживается.
Для подключения к конференции ключ API не требуется; вход участника выполняет Толк.

## Корпоративная аутентификация

Нажмите «Войти через SSO пространства»: окно всегда начинается на `app.ktalk.ru`.
Выберите там «Вход с корпоративной учётной записью (SSO)» и введите тот же адрес
пространства компании, который указан в настройках модуля. Завершите вход в своей
корпоративной системе. Aster сохраняет сессию только этого пространства Толка;
стартовая страница не подменяет сервер API. Host выделяет непостоянную Electron session
без почтовых cookies и учётных данных Exchange. Пароль не получает модуль.

Host читает только сессию на точном origin Толка и сохраняет токен
в независимом зашифрованном профиле модулей Aster Mail.
Токен не возвращается JS-коду модуля, не включается в каталог, файлы пакета и логи.
Посредник добавляет `Authorization: Session …` только к запросам того же пространства.
Временные данные окна очищаются после входа/отмены, отключения и смены аккаунта.
Окно ограничено пятью минутами; скрытого обновления сессии нет. «Удалить сессию Толка»
удаляет локальный токен; для серверного отзыва используйте средства Толка.

Во время явного SSO допускается переход на HTTPS-сервер корпоративной системы
входа без добавления домена в пакет. Это относится только к выделенному окну
входа: сам модуль не получает сетевой доступ к IdP, его cookies или токены.
Сессия сохраняется только после возврата в настроенное пространство Толка.
HTTP, отключение TLS и запуск внешних протоколов не поддерживаются.

Адаптер проверен на формате публичного веб-клиента Толка `master-d436cf83`:
`localStorage.session.data` с `token` и `expiresAt`, без anonymous. Это зависимость
от формата веб-клиента, а не универсальный OAuth SDK. Изменение формата потребует
обновления адаптера; неподходящий токен не сохраняется. Конкретный корпоративный
SSO и Windows пока не проверены; могут потребоваться дополнительные origins,
сертификаты и проверка особенностей корпоративного провайдера.

## API-ключ

Ключ создаёт администратор пространства Толка: **Управление → API ключи → Добавить**.
Обычный участник может попросить его у администратора или воспользоваться
корпоративным входом в настройках модуля. Для перехода в готовую комнату ключ не нужен.

Альтернатива входу — ключ пространства с правами `application.rooms.read` и
`application.rooms.write`, подходящим сроком и ограничениями IP. Он хранится
в зашифрованных настройках модуля через Aster LocalStore, не отображается повторно.
При наличии ключа используется он; после удаления — сессия выбранного сервера.
Отказ ключа не переключает авторизацию автоматически. Серверный отзыв ключа
выполняется администратором; кнопка удаления очищает локальную копию.

Официальный API требует `X-Auth-Token`. `X-API-Key` для внутренних приложений
не используется. При 401/403 проверьте вид ключа, права, срок, IP и доступность API
в вашем сервисе/тарифе. Обход ограничений не выполняется.

## Создание комнаты и приглашение

В форме **новой встречи** есть одна кнопка модуля — **«Создать комнату»**.
Она создаёт комнату с названием встречи (или «Новая встреча») и сразу добавляет
ссылку в место встречи, если оно пустое, и в конец описания. Введённая повестка
и заполненное место сохраняются. Повторное нажатие в этом черновике использует
ту же комнату. Настроек входа и отдельных форм модуля в календаре нет.

В карточке уже созданной встречи нажмите **«Подключиться»**: если ссылка относится
к настроенному пространству Толка и модуль включён, сразу открывается установленное
приложение Толк. Кнопка создания комнаты в редактировании сохранённой встречи
не показывается.

При создании отправляется только название;
участники и описание встречи в Толк не передаются. Новый адрес — `aster` + случайный
UUID без дефисов. После GET-проверки настроек адреса модуль один раз делает
`PUT /api/Rooms/{roomName}` с `{ "title": "…" }`.

GET не является проверкой существования: для нового адреса Толк может вернуть
HTTP 200 и настройки по умолчанию. Это проверено анонимным чтением публичного
демопространства. Модуль принимает такой ответ только при совпадении `roomName`,
пустых названии/описании, списках модераторов, участников и сессионных залов,
без PIN и включённой/активной трансляции. Пустые объекты SIP/трансляции и SIP-реквизиты
только для чтения не доказывают занятость адреса и не блокируют PUT.
Настроенная или активная комната блокирует PUT;
неожиданный формат и чужой `roomName` также блокируют запись. При GET 404
сценарий создания по-прежнему доступен.

В настройках отображается последняя попытка даже без созданной комнаты: адрес,
время, результат GET, отправка/результат PUT и последующая проверка. SDK возвращает
тело успешного ответа без точного статуса, поэтому успех обозначен `HTTP 2xx`;
статусы ошибок показываются точно. Сохраняется одна запись в зашифрованном профиле,
только с флагами наличия названия и числом модераторов/участников. Полные ответы,
названия, контакты, идентификаторы конференций и заголовки авторизации туда не копируются.
Сброс настроек очищает эту запись; обновление сохраняет её. PIN, наличие SIP-реквизитов,
включение и активность трансляции отображаются отдельно; SIP-адреса и ключи трансляции
не сохраняются в этой записи. В поле «Место» и описание встречи вставляется только
HTTPS-адрес комнаты, а не SIP или адрес трансляции.

Сохранённая SSO-сессия сама по себе не подтверждает доступ к API комнат.
При отказе предварительного GET модуль показывает HTTP-статус и явно сообщает,
что запрос создания не отправлялся. 401 требует повторного входа, 403 — проверки
прав пользователя или ключа в пространстве; 429 — ожидания перед новой попыткой.
Ответы сервиса и токены в сообщениях не показываются. Если же PUT уже отправлен
и результат неизвестен, используйте «Проверить комнату» в настройках: повторной
записи не будет.

Этот PUT также обновляет существующую комнату. Поэтому ручной идентификатор новой
комнаты не предлагается. GET не доказывает отсутствие ранее сохранённой пустой
комнаты и не даёт атомарной гарантии отсутствия гонки; случайный
128-битный адрес делает коллизию крайне маловероятной. Серверная идемпотентность
не заявляется. Для новых идентификаторов официальный API разрешает строчные
латинские буквы и цифры; готовые ссылки с подчёркиванием, как `test_room`, допустимы
для вставки и входа.

Намерение и ссылка сохраняются **до** записи. При обрыве, timeout, ошибке JSON
или неожиданном ответе результат остаётся неизвестным. Повторного PUT нет даже
после перезапуска. «Проверить комнату» делает только GET. 404 после обрыва не доказывает,
что отложенная запись не завершится: проверьте Толк перед новым созданием.
Другую комнату можно начать после явного завершения предыдущего сценария.
Это не удаляет комнату на сервере; закрытие черновика также её не удаляет.

Ссылка вставляется автоматически. Усечённое/слишком длинное описание
не перезаписывается — скопируйте готовую ссылку из настроек модуля и добавьте её вручную. Приглашение отправляет пользователь
в обычной форме Aster Mail. Планирование и повторы остаются в календаре Exchange.

## Свой сервер и IdP

Новый origin требует отдельного пакета с явными правами:

```sh
npm run package:ktalk -- --server https://company.ktalk.ru --out dist/company --version 0.1.6 --identity-origin https://sso.company.ru
```

`--identity-origin` необязателен, может повторяться. Поддерживается HTTPS-сервер
собственной установки, включая порт, если он совместим с API и десктопным Толком.
Сборщик фиксирует origins в manifest и конфигурации, не перезаписывает папку
существующего пакета. Для изменённого опубликованного пакета нужна новая версия.
Полученную папку подключите в Aster Mail, повторно проверив разрешения.

## Проверки и источники

Тесты используют вымышленные ответы, отдельный Electron профиль и перехваченный вход.
Проверяются изоляция, сохранение сессии, отсутствие токена в SDK/каталоге, запись
без повтора, сохранение описания, смена аккаунта и панель 100/150/200%.
Реальные комнаты/приглашения, подключение к конференции и корпоративный SSO в тестах
не выполняются.

- [Официальный API](https://developer.kontur.ru/doc/talk.public.api).
- [Ключ пространства](https://support.kontur.ru/talk/46831-klyuch_api).
- [Персональный ключ](https://support.kontur.ru/talk/86797-personalnyj_apiklyuch_dostupa_v_tolke).
- [Десктоп и корпоративное пространство](https://support.kontur.ru/talk/87427-oshibki_desktop_prilozheniya).

`ktalk://<server>/<room>` подтверждён схемой и обработчиком установленного Толка
`3.7.0` на macOS. Код приложения не копировался. При отсутствии обработчика host
покажет ошибку и не откроет второй адрес скрытно.


## Свой домен пространства

В поле «Сервер пространства» можно ввести, например, `https://diy.ktalk.ru`.
При сохранении Aster Mail запросит разрешение на этот точный origin; до согласия
модуль не получает к нему доступ и не меняет сохранённый сервер/ключ.
Разрешение относится к текущему модулю и охватывает его API, вход
и ссылки приложения встречи. Адрес в `networkOrigins` — готовый вариант,
а не полный список поддерживаемых пространств. Поддомены семейства `ktalk.ru`
объявлены через общий SDK `optionalOrigins`, без неограниченного сетевого доступа.

Домен за пределами этого семейства или отдельный корпоративный IdP требует
проверенного пакета с точными origins (см. команду подготовки своего пакета).
Удаление модуля удаляет и дополнительные разрешения; повторное подключение
начинается без них. Смена сервера не переносит API-ключ предыдущего сервера.

## Обновление

Используйте «Обновить с сохранением настроек» в каталоге совместимого клиента.
Удалять модуль перед обновлением не нужно: сохраняются сервер, API-ключ, состояние
комнат и выданные разрешения. Записи неизвестного результата не повторяются.
`settingsVersion: 1` не меняет структуру этих данных. При будущей смене схемы
пакет должен объявить проверенную цепочку миграций SDK.


## Очистка настроек

«Удалить сессию Толка» завершает сервисный вход, сохраняя сервер и API-ключ.
«Сбросить все настройки Толка» с подтверждением прямо на кнопке очищает сервер,
API-ключ, сессию и локальное состояние комнат. Поле сервера после сброса пустое.
Существующие комнаты на сервере не удаляются. Если результат создания неизвестен,
сначала проверьте комнату и явно завершите этот сценарий, чтобы не потерять его
при сбросе. Обновление пакета и переустановка самого Aster Mail сохраняют настройки;
полное удаление модуля через его строку очищает их.
